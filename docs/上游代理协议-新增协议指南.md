# 上游代理协议新增指南

本文说明如何在 mihomo 代码里新增一个自定义上游代理协议。

目标场景是：

- 你想在 `proxies:` 里增加一个新的 `type`
- 例如：

```yaml
proxies:
  - name: my-proxy
    type: myproto
    server: 1.2.3.4
    port: 12345
```

- 然后让 mihomo 能按这个 `type` 建立到远端服务器的连接

本文以当前仓库代码结构为准。

## 1. 整体接入路径

新增一个上游协议，最小链路通常是：

1. 新增一个出站实现文件  
   例如：
   - `adapter/outbound/myproto.go`

2. 定义配置结构  
   例如：
   - `MyProtoOption`

3. 定义适配器结构  
   例如：
   - `MyProto`

4. 实现构造函数  
   例如：
   - `NewMyProto(option MyProtoOption) (*MyProto, error)`

5. 在代理解析器中注册 `type`
   - [adapter/parser.go](/vm/project/github/clash-meta/mihomo/adapter/parser.go:12)

6. 在 `constant.AdapterType` 中增加类型枚举和字符串
   - [constant/adapters.go](/vm/project/github/clash-meta/mihomo/constant/adapters.go:18)

7. 按需补示例配置、测试和文档

最重要的事实是：

- `proxies:` 里的 `type` 不是自动发现的
- 必须在 [adapter/parser.go](/vm/project/github/clash-meta/mihomo/adapter/parser.go:12) 里显式加分支

## 2. 先看现有实现模板

最适合作为起点的参考实现是：

- TCP + 可选 UDP 代理：  
  [adapter/outbound/socks5.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/socks5.go)

- 纯 TCP CONNECT 类代理：  
  [adapter/outbound/http.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/http.go)

- 更复杂的协议实现：  
  [adapter/outbound/vless.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/vless.go)

如果你的新协议只是“先连远端，再做一次握手，然后转发 TCP”，优先参考 `http.go` 或 `socks5.go`。

## 3. 必改文件清单

新增一个最小可用协议，通常至少要改这几个位置：

### 3.1 新增协议实现文件

例如：

- `adapter/outbound/myproto.go`

这个文件里一般会包含：

- `type MyProto struct`
- `type MyProtoOption struct`
- `func NewMyProto(...)`
- `func (m *MyProto) DialContext(...)`
- 如果支持 UDP，再实现 `ListenPacketContext(...)`

### 3.2 注册新的 `type`

在：

- [adapter/parser.go](/vm/project/github/clash-meta/mihomo/adapter/parser.go:12)

里新增分支，例如：

```go
case "myproto":
    myOption := &outbound.MyProtoOption{BasicOption: basicOption}
    err = decoder.Decode(mapping, myOption)
    if err != nil {
        break
    }
    proxy, err = outbound.NewMyProto(*myOption)
```

没有这一步，配置文件里的：

```yaml
type: myproto
```

会直接报：

```text
unsupport proxy type: myproto
```

### 3.3 增加适配器类型枚举

在：

- [constant/adapters.go](/vm/project/github/clash-meta/mihomo/constant/adapters.go:18)

里加一个新的 `AdapterType`，例如：

```go
MyProto
```

同时在 `String()` 里补：

```go
case MyProto:
    return "MyProto"
```

没有这一步，日志、API 输出、JSON 序列化里的类型名会不完整。

## 4. 最小协议实现应该长什么样

### 4.1 配置结构体

大多数协议都需要一个 `Option` 结构体，字段用 `proxy:"..."` tag 暴露给配置解析器。

例如：

```go
type MyProtoOption struct {
    BasicOption
    Name     string `proxy:"name"`
    Server   string `proxy:"server"`
    Port     int    `proxy:"port"`
    Password string `proxy:"password,omitempty"`
    UDP      bool   `proxy:"udp,omitempty"`
}
```

这里的 `BasicOption` 很重要，定义在：

- [adapter/outbound/base.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/base.go:169)

它已经帮你接好了这些公共能力：

- `tfo`
- `mptcp`
- `interface-name`
- `routing-mark`
- `ip-version`
- `dialer-proxy`

以及：

- `option.NewDialer(...)`

所以不要自己重复造一套基础拨号配置。

### 4.2 协议结构体

最常见写法是组合 `*Base`：

```go
type MyProto struct {
    *Base
    option *MyProtoOption
}
```

`Base` 定义在：

- [adapter/outbound/base.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/base.go:23)

它已经提供了：

- 名称
- 地址
- 适配器类型
- UDP 能力标记
- `ProxyInfo()`
- `DialOptions()`
- `ResolveUDP()`

### 4.3 构造函数

最小构造函数通常长这样：

```go
func NewMyProto(option MyProtoOption) (*MyProto, error) {
    outbound := &MyProto{
        Base: NewBase(BaseOption{
            Name:         option.Name,
            Addr:         net.JoinHostPort(option.Server, strconv.Itoa(option.Port)),
            Type:         C.MyProto,
            ProviderName: option.ProviderName,
            UDP:          option.UDP,
            TFO:          option.TFO,
            MPTCP:        option.MPTCP,
            Interface:    option.Interface,
            RoutingMark:  option.RoutingMark,
            Prefer:       option.IPVersion,
        }),
        option: &option,
    }
    outbound.dialer = option.NewDialer(outbound.DialOptions())
    return outbound, nil
}
```

这套模式和现有协议是一致的，例如：

- [adapter/outbound/socks5.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/socks5.go:169)
- [adapter/outbound/http.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/http.go:147)

## 5. TCP 支持怎么实现

如果你的协议支持 TCP，核心是实现：

```go
func (m *MyProto) DialContext(ctx context.Context, metadata *C.Metadata) (_ C.Conn, err error)
```

最常见模式是：

1. 先连上你的远端代理服务器
2. 执行协议握手
3. 用 `metadata` 里的目标地址告诉远端要访问哪个目标
4. 返回 `NewConn(c, m)`

参考最小模式：

```go
func (m *MyProto) DialContext(ctx context.Context, metadata *C.Metadata) (_ C.Conn, err error) {
    c, err := m.dialer.DialContext(ctx, "tcp", m.addr)
    if err != nil {
        return nil, fmt.Errorf("%s connect error: %w", m.addr, err)
    }

    defer func(c net.Conn) {
        safeConnClose(c, err)
    }(c)

    err = m.handshake(ctx, c, metadata)
    if err != nil {
        return nil, err
    }

    return NewConn(c, m), nil
}
```

现有参考：

- [adapter/outbound/http.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/http.go:62)
- [adapter/outbound/socks5.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/socks5.go:70)

### `metadata` 有什么用

`metadata` 就是当前这条连接真正要访问的目标。

常见用法：

- `metadata.RemoteAddress()`
- `metadata.Host`
- `metadata.DstIP`
- `metadata.DstPort`

例如 HTTP CONNECT 代理就是把：

- `host:port`

写进 CONNECT 请求里，见：

- [adapter/outbound/http.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/http.go:87)

## 6. UDP 支持怎么实现

如果协议支持 UDP，还要实现：

```go
func (m *MyProto) ListenPacketContext(ctx context.Context, metadata *C.Metadata) (_ C.PacketConn, err error)
```

这通常比 TCP 难，因为你需要考虑：

- 远端 UDP 建链方式
- 是否需要先通过 TCP 做 UDP Associate
- 如何封包/拆包
- 是否要求先解析目标 IP

例如 SOCKS5 的 UDP 实现可参考：

- [adapter/outbound/socks5.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/socks5.go:89)

一个关键点是：

如果你的 UDP 协议要求目标必须是 IP，不是域名，通常要先：

```go
if err = m.ResolveUDP(ctx, metadata); err != nil {
    return nil, err
}
```

`ResolveUDP()` 由 `Base` 提供，见：

- [adapter/outbound/base.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/base.go:155)

## 7. `ProxyInfo()`、`SupportUDP()`、`SupportUOT()`

### `SupportUDP()`

通常不需要单独实现，`Base` 已根据 `UDP` 字段返回，见：

- [adapter/outbound/base.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/base.go:101)

### `SupportUOT()`

默认 `Base` 返回 `false`，见：

- [adapter/outbound/base.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/base.go:97)

如果你的协议支持 UDP over TCP，需要自己覆写。

### `ProxyInfo()`

如果只是想继承基础信息，一般直接沿用 `Base.ProxyInfo()`。  
如果你还想把 `DialerProxy` 之类的额外信息暴露出来，可以像现有协议这样覆写：

- [adapter/outbound/http.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/http.go:81)
- [adapter/outbound/socks5.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/socks5.go:155)

## 8. `StreamConnContext()` 不是必须，但很常见

很多协议会把“对已经建立的 TCP 连接做二次封装/握手”单独拆成：

```go
func (m *MyProto) StreamConnContext(ctx context.Context, c net.Conn, metadata *C.Metadata) (net.Conn, error)
```

这样好处是：

- `DialContext()` 更短
- 如果后续还要支持链式复用，逻辑更清晰

参考：

- [adapter/outbound/socks5.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/socks5.go:46)
- [adapter/outbound/http.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/http.go:45)

## 9. 最小代码骨架

下面是一份足够接近现有风格的最小骨架：

```go
package outbound

import (
    "context"
    "fmt"
    "net"
    "strconv"

    C "github.com/metacubex/mihomo/constant"
)

type MyProto struct {
    *Base
    option *MyProtoOption
}

type MyProtoOption struct {
    BasicOption
    Name   string `proxy:"name"`
    Server string `proxy:"server"`
    Port   int    `proxy:"port"`
    UDP    bool   `proxy:"udp,omitempty"`
}

func (m *MyProto) DialContext(ctx context.Context, metadata *C.Metadata) (_ C.Conn, err error) {
    c, err := m.dialer.DialContext(ctx, "tcp", m.addr)
    if err != nil {
        return nil, fmt.Errorf("%s connect error: %w", m.addr, err)
    }

    defer func(c net.Conn) {
        safeConnClose(c, err)
    }(c)

    err = m.handshake(ctx, c, metadata)
    if err != nil {
        return nil, err
    }

    return NewConn(c, m), nil
}

func (m *MyProto) handshake(ctx context.Context, c net.Conn, metadata *C.Metadata) error {
    // TODO: 实现你的协议握手
    // metadata.RemoteAddress() 往往就是你要告诉远端的目标地址
    return nil
}

func NewMyProto(option MyProtoOption) (*MyProto, error) {
    outbound := &MyProto{
        Base: NewBase(BaseOption{
            Name:         option.Name,
            Addr:         net.JoinHostPort(option.Server, strconv.Itoa(option.Port)),
            Type:         C.MyProto,
            ProviderName: option.ProviderName,
            UDP:          option.UDP,
            TFO:          option.TFO,
            MPTCP:        option.MPTCP,
            Interface:    option.Interface,
            RoutingMark:  option.RoutingMark,
            Prefer:       option.IPVersion,
        }),
        option: &option,
    }
    outbound.dialer = option.NewDialer(outbound.DialOptions())
    return outbound, nil
}
```

## 10. 配置解析怎么接上

除了新增 `myproto.go`，还要在：

- [adapter/parser.go](/vm/project/github/clash-meta/mihomo/adapter/parser.go:12)

加上：

```go
case "myproto":
    myOption := &outbound.MyProtoOption{BasicOption: basicOption}
    err = decoder.Decode(mapping, myOption)
    if err != nil {
        break
    }
    proxy, err = outbound.NewMyProto(*myOption)
```

这样配置文件里的：

```yaml
proxies:
  - name: my-proxy
    type: myproto
    server: 1.2.3.4
    port: 12345
```

才能真正解析成功。

## 11. 还要不要改示例配置

建议改。

最少应该在：

- [docs/config.yaml](/vm/project/github/clash-meta/mihomo/docs/config.yaml)

补一个你的新协议示例，不然用户只能读代码猜字段名。

## 12. 测试建议

至少做三层测试：

### 12.1 构造函数测试

验证：

- 必填字段缺失时报错
- 合法参数能正确创建实例

参考现有模式：

- [adapter/outbound/mieru_test.go](/vm/project/github/clash-meta/mihomo/adapter/outbound/mieru_test.go)

### 12.2 解析器测试

验证：

- `type: myproto` 能被 `ParseProxy` 正确解析
- `proxy:"..."` tag 对应的字段能正确填充

### 12.3 端到端协议测试

如果协议复杂，最好有一个最小可控的假服务端，验证：

- TCP 建连
- 握手
- 目标地址传递
- UDP 能力（如果支持）

## 13. 实施顺序建议

推荐顺序：

1. 先加 `AdapterType`
2. 再写 `MyProtoOption` + `NewMyProto`
3. 先只做 TCP `DialContext`
4. 接上 `adapter/parser.go`
5. 配一个最小示例手工验证
6. 再补 UDP
7. 最后补测试和文档

这样可以最快跑通“从配置到拨号”的主路径。

## 14. 常见坑

### 14.1 只写了协议文件，忘了注册 parser

结果：

- 配置加载直接报 `unsupport proxy type`

### 14.2 忘了加 `AdapterType`

结果：

- 类型字符串、日志、API 输出不完整

### 14.3 没有使用 `BasicOption`

结果：

- `dialer-proxy`
- `routing-mark`
- `interface-name`
- `ip-version`

这些现有公共能力丢失

### 14.4 UDP 协议没先 `ResolveUDP()`

结果：

- 某些只接受 IP 的远端协议在域名场景下直接失败

### 14.5 没有用 `safeConnClose`

结果：

- 失败路径容易泄漏底层连接

## 15. 一句话总结

在 mihomo 里新增一个自定义上游协议，最小必要步骤是：

- 新增一个 `adapter/outbound/<proto>.go`
- 定义 `Option` 和 `New<Proto>()`
- 实现 `DialContext()`，按需实现 `ListenPacketContext()`
- 在 `adapter/parser.go` 注册新的 `type`
- 在 `constant/adapters.go` 增加对应 `AdapterType`

跑通这条链路后，这个新协议就能在 `proxies:` 里像 `socks5`、`vmess`、`trojan` 一样被使用。
